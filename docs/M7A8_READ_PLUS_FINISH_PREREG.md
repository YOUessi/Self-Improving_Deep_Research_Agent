# M7-A8 pre-registration: real supporting-READ preference + FINISH auxiliary (2026-10-27)

This protocol was written **before** M7-A8 GPU training and comparison. Source branch is `feat/m7-onpolicy-agent-grpo`; the M7-A7 reports are already negative on public HotpotQA DEV32, so **do not tune** by re-inspecting those outcomes. Keep sealed final-B160 untouched.

## Falsifiable hypothesis

M7-A7 FINISH-only TRAIN-gold supervised auxiliary (weight 0.2) decreased READ calls and original-support recall in both fixed public DEV32 seeds, despite some improvement on biased TRAIN-heldout58. M7-A8 tests whether adding missing-support READ supervision in already-visited legal states prevents premature FINISH / missing evidence. **This is a hybrid: genuine on-policy multi-turn group-relative policy gradient PLUS explicitly TRAIN-only supervised preferences, never pure GRPO or unsupervised RSI.** Failure (no strict EM+support gain or higher tool cost) is a substantive negative result, not a reason to use DEV labels for further selection.

## Pre-specified interventions and frozen data

- **Frozen checkpoint:** Qwen3-0.6B-Base + original TRAIN-only `qwen3_06b_sft40_stop_curriculum_seed43` stop-SFT LoRA, `answer_proposer=v4`, the same frozen nonoracle legal-action catalog and observation-only V4 biases as M7-A7.
- **Existing comparison arms:** original stop-SFT, pure group-relative GRPO (M7-A7 `M7A7_CONTROL_s153_G20x4_U2_d0589ad8`), and FINISH-only hybrid (M7-A7 `M7A7_HYBRID_s153_G20x4_U2_d0589ad8`). All same parent and training question seed. Existing checkpoints will be loaded for evaluation, **not re-trained**; verify SHA and provenance before any comparison.
- **New intervention:** one M7-A8 **FINISH+READ hybrid**, from the SAME frozen stop-SFT parent; **TRAIN seed 153**, **20 distinct TRAIN curriculum questions per optimizer update × 4 live model-sampled full tool trajectories per question × 2 updates**, `credit_mode=episode_total`, `lr=3e-6`, `finish_aux_weight=0.2`, `read_aux_weight=0.2`. Exactly the original TRAIN-only `v4_bridgeprior_teacher1024_s43_4215c05e` success-reachable curriculum, `max_steps=6`, `max_tool_calls=5`, `max_context=2048`.
- **READ auxiliary:** post-hoc gold-support labels only for actual *previously searched, still unread* original TRAIN supporting-document IDs offered as legal READ choices at an actual sampled state. Gold is **never** exposed in policy prompts, search queries, candidate generator, observational action priors, tool responses or the selected live action. Replayed forged READ, unretrieved support, invalid sample/trace mismatch fail closed. Single-token legal action logprobs and biases in supervised objective must be identical to behavior policy. TRAIN support labels for optimizer are **supervised imitation**, not policy-gradient rewards.
- **Primary development gate:** an independently frozen, *disjoint from all recorded M7 GPU TRAIN fits and TRAIN teacher success/heldout rows*, 64-question sample drawn from the original 1,024 TRAIN questions. Before training, exclude all IDs appearing in any existing M7 `data/*/TEACHER_ACTIONS_*.jsonl` and `results/*/TRAIN_SUMMARY.json` `selected_training_ids`; 402 IDs excluded; sort remaining 622 by SHA256(`M7A8-FROZEN-HOLDOUT-919:` + question ID), take first 64. Ordered ID digest: `336fa32d645a2b52cf68563a56dc9d6571819971c872a92cfb790e2876fcda81` (SHA256 of newline-joined IDs, no final newline). Freeze exact question IDs and all original scope-preserving document rows in a Tang-only immutable dataset prior to GPU training. No model fit may access those 64 labels as reward. This is **within TRAIN**, not a final independent data source, and the TRAIN teacher previously attempted the 1,024-Q pool; it is a meaningful non-overlap engineering evaluation, not external generalization.
- **Secondary smoke gate:** previously viewed frozen public DEV pilot32; state-keyed stochastic action seeds **151 and 157** reused exactly for all arms; DEV gold must not enter optimizer or action priors. Never access final-B160 and do not peek at eval-A64 during this iteration. Neither DEV32 nor teacher-heldout58 is an independent untouched validation set anymore.

## Measurements and promotion gate

For each arm / dataset, use **identical** pinned source, fixed dataset bytes, policy, finite-action sampler, seeds, full Search/Read/Finish, tool budgets and question ordering. Report per-question paired differences in (1) answer exact match, (2) strict answer+original support citations, (3) original support recall, (4) tool calls/model calls, (5) read calls and premature FINISH vs abstention. In two-seed DEV repeated-question analysis bootstrap by **question ID cluster** preserving both seeds, never treat 64 stochastic DEV episodes as 64 independent QA examples. For the new TRAIN64 use a single preregistered stochastic seed **171** first (optionally 173 as replication); question-cluster bootstrap with deterministic seed 919 and 5,000 draws.

A8 succeeds the *exploratory engineering* gate only if it yields positive paired EM **and** strict original citation success on fresh TRAIN64, without an unacceptable tool-call increase, and does not regress original-support recall in frozen DEV smoke. Improvements on DEV32 alone do **not** support generalization. To claim reliable GRPO improvement, the **pure** on-policy control must independently improve on truly independent frozen QA with paired uncertainty; **a hybrid supervisory gain is not a pure GRPO gain**. No checkpoint is promoted solely for weight SHA changes, reward variance or biased TRAIN training success.
