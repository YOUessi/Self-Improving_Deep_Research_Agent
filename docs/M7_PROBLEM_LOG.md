- **P-M7-007 — Lexical answer mention is not entailment; cross-document token concatenation can create phantom citations.** Actual model's opened pilot32 observation-only verifier found 28/32 (both stop and bridge policies) contain answer text in some single cited READ document, but this says nothing about whether the source entails the answer; M6 separately previously reported EM6/32 stop and EM3/32 bridge. A split `new` / `york` across two cited documents can fool concatenated-source checks, and `Not Paris` contains `Paris` but should never become semantic approval. **Action:** opt-in source-only diagnostic requires lexical token sequence within ONE cited READ document; always mark semantic entailment as `not_evaluated`, and test hallucinated/duplicate citations and negations. Do not change default EvidenceAudit to an unsupported NLI label.
- **P-M7-008 — TRAIN repeated rollouts are correlated, do not resample 48 individual episodes as 48 questions.** Implemented deterministic **question-cluster bootstrap** (12 or 8 real question units, full group-of-4 episodes), fixed seed2027 and 2,000 resamples. Small-cluster uncertainty retained and intervals show no robust complete-read or answer+sentence success. Original TRAIN `original_train_subset.json` found and SHA pinned; labels consumed **only** by offline audit after each actual SearchAgent rollout. Tested **111 CPU tests** + green GitHub Actions at source SHA `6185e55051ac25e353623355633c1d0122d7bd6c`.
- **P-M7-009 — BM25 stopwords silently erased wh interrogatives needed for query-rewrite relation extraction.** A pre-data unit test expected `Congress of Vienna austrian statesman` but got `Congress of Vienna chaired austrian statesman`; root cause `retrieval.tokenize(question)` strips `what` before tail segmentation. **Resolution:** parse raw lowercase question words to find the last wh-question word, then filter irrelevant suffix tokens. Fixed `c5546f33e97d6bea963a5c97678f07050c7d3add`.
- **P-M7-010 — Untrusted evaluator event could change future plan despite no direct gold read.** Injecting an `eval_only` observation after real READ caused relation-tail branch to skip rewriting based on `observations[-1].kind`, potentially leaking evaluator metadata into action timing. **Resolution:** explicitly filter to allowed SEARCH/READ observation kinds before *all* relation planning and fallback delegation. Fixed `a5e1777e537fd9d616576186a49ec8cca6a64568`; unit tests cover gold perturbation. Subsequent **116/116 Tang CPU tests passed**, original two failures reproduced and resolved. No live policy or hidden eval labels involved.
- **P-M7-011 — TRAIN-only question-tail rewrite does NOT generalize on the opened pilot32.** Pre-registered two disjoint TRAIN64 cohorts improved complete READ **27→30** each under unchanged budget, but independent frozen open pilot32 saw *worse* complete retrieval **22→20**, **equal** complete READ **16→16**, and **slightly higher** tool calls 3.59375→3.625. Report and immutable raw run paths in `docs/M7_E023_RELATION_TAIL_REWRITE_ABLATION.md`.
