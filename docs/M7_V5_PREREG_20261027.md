# M7 V5 finite-action answer catalog — preregistered real Agent A/B (2026-10-27)

This document is written **before** the V4/V5 actual model-policy pilot evaluation.

## Research question and change

The FINISH choice catalog of existing V4 has at most four populated answer actions. On TRAIN1024 with post-hoc oracle READ exposure, V4 offered the correct answer for 403/1024; a V5 expanded interleaved two-read-source catalog with structural polar yes/no alternatives offered it for **564/1024** (+161; +15.72 percentage points). On already-viewed DEV pilot32, 9/32→12/32. These **are not model answer accuracy** because gold sources were hypothetically READ in the *offline evaluator* only.

V5 added to `FiniteActionConfig(answer_proposer="v5")`, CLI and `build_legal_actions`; it keeps at most **10 actions / one ASCII-digit LM token**, the mandatory last `finish(answer="")` abstention, and up to 2 exposed-but-unread READ actions plus one SEARCH action before using remaining slots for evidence-derived FINISH options. It preserves V3/V4's requirement for **two distinct actually READ sources** before any nonempty FINISH and cites only these READ sources. Every candidate is derived from question+actual tool observations, never evaluator gold. V5 uses the same observation-only `action_logit_biases` as V4. The single-token sampled probability and differentiable log-prob still use exact same legal-mask+bias Softmax. V4 path is unchanged.

## Fixed A/B protocol

- **Model:** identical Qwen3-0.6B-Base + pre-existing TRAIN-only M5 stop-SFT LoRA, SHA256 `44e559a3d6bc61f46b5a736d0c8ff4f896c281e2139ff12f967ed4b7cc69d771`. No new weights trained in this stage.
- **Dataset:** already-viewed DEV pilot32 under `~/experiments/sidra_m4/data/frozen_seed42_32p_224h/pilot/converted`; gold withheld from online policy. TRAIN1024 coverage diagnostic is not a train/eval score.
- **Arms:** V4 and V5 under same **canonical new GitHub source snapshot** after this preregistration. Both use exactly same task IDs, real SearchAgent BM25 tools, scope, `max_steps=6`, `max_tool_calls=5`, `search_top_k=3`, `max_context=2048`, Qwen3 non-thinking, categorical masked action selection. Only `--answer-proposer` changes. Sampling seeds **151 and 157**, question-state-keyed RNG used in both. Compare per question without treating two seeds as 64 independent questions.
- **Primary:** exact answer EM **AND** strict answer + gold-support citation. Secondary support recall, finish/abstain/errors, average searches/reads/model calls, prompt/completion tokens, elapsed time.
- **Selection:** V5 may proceed to a TRAIN-only online GRPO pilot **only if** the same-checkpoint real Agent shows nonnegative strict success, no material answer regressions, and either strictly improved answer EM or verified success across fixed seeds, with a budget-cost explanation. The offline candidate upper bound alone is insufficient. If it fails, prioritize answer generator decoupling rather than accumulating policy updates.
- **Further verification:** A/B on separate TRAIN-only untouched cohorts must be frozen with cross-workstream exposure audit **before** training or promoting. DEV final-B160 is sealed and must remain unexamined. Existing eval-A64 has prior exposure and is not fresh.
- **All outcomes including no gains must be retained.** Model/GPU computations on Tang with a shared cooperative GPU0 lock, no lingering vLLM service and no disruption of other workstreams.

## Limitations

V4 versus V5 is a **change to the policy's legal action space**, not a fair treatment-versus-control of a single policy-gradient training run. We can compare the *same checkpoint under two policy classes*, but it is invalid to ascribe gains to GRPO. V5 increases answer options while possibly reducing search/research action diversity. Test both QA correctness and tool cost. Original HotpotQA distractor is per-question 10-candidate passage retrieval, not full-Wikipedia or real open-web search. Existing 'strict' check uses gold support passages, not semantic entailment.
